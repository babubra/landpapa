# Архитектура базы данных для SEO-блоков

Для реализации динамических блоков на главной странице (таких как "Участки в Гурьевском районе", "Участки ИЖС" и т.д.) нам потребуется новая таблица `seo_blocks` (или `featured_groups`).

Эта таблица будет служить "правилом" для бэкенда: как собрать группу из 3-4 листингов для главной страницы и куда должна вести ссылка "Смотреть все".

## Новая модель: `seo_blocks`

Файл: `backend/app/models/seo_block.py`

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `id` | Integer | Primary Key |
| `title` | String(255) | Заголовок блока (напр., "Участки ИЖС") |
| `subtitle` | String(255) | Подзаголовок (напр., "Отличный вариант для строительства") |
| `link_url` | String(255) | Ссылка при клике на "Смотреть все" (напр., `/catalog/gurevskiy-rayon`) |
| `location_id` | Integer (FK) | Связь с таблицей `locations` (опционально, для фильтрации листингов по району/поселку) |
| `land_use_filter` | String(50) | Фильтр по типу использования (опционально: `izhs`, `snt`) |
| `sort_order` | Integer | Порядок вывода на главной (0, 1, 2...) |
| `is_active` | Boolean | Включен/отключен блок (default: True) |

### Как это будет работать (Сценарий):

1. **Админка**: Контент-менеджер создает новый "SEO блок" -> Пишет название "Участок у моря" -> Выбирает привязку к локации `Зеленоградский район` -> Задает ссылку `/catalog/zelenogradskiy-rayon`.
2. **FastAPI (Бэкенд)**: Эндпоинт `GET /api/public/seo-blocks` берет все активные блоки. Для каждого блока он выполняет внутренний запрос к таблице `listings`, фильтруя активные объявления по `location_id` (и `land_use_filter`, если есть). Берет ТОП-4 карточки.
3. **Next.js (Фронтенд)**: Компонент пробегается по массиву блоков и рендерит:
   
   ```
   [Заголовок Блока]               [Кнопка "Смотреть все" -> link_url]
   [Карточка 1] [Карточка 2] [Карточка 3] [Карточка 4]
   ```
